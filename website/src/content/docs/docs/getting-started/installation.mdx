Every release on the [releases page](https://github.com/bitknox/anistream/releases) ships the same
build several ways:

- An installer: `.pkg` on macOS, `setup.exe` on Windows, `.deb` on Debian and Ubuntu. Each one
  puts `anistream` on your `PATH` and adds a launcher, so you can type it or click it. The
  launcher opens your terminal, since that is where anistream lives.
- An AppImage for every other Linux distro. `chmod +x` it and run it from a terminal. Nothing is
  installed. Like the `.deb` and the `.tar.gz`, it needs glibc 2.28 or newer: Debian 10, Ubuntu
  20.04, RHEL 8 or later.
- An archive, `.tar.gz` or `.zip`, for putting the binary on `PATH` yourself. It holds the binary,
  the README, the licence and a `third-party` folder with the notices for what anistream bundles.

Everything ships with a `.sha256` worth checking first.

:::caution[Not code-signed]
The releases are not signed, so the first open takes one extra step:

- On macOS, opening the `.pkg` says Apple could not verify it. Choose **Done**, go to
  **System Settings → Privacy & Security**, find the line about anistream near the bottom and
  choose **Open Anyway**.
- On macOS, a binary from an archive downloaded with a browser is refused the first time it runs.
  Clear the download flag once with `xattr -d com.apple.quarantine anistream`.
- On Windows, SmartScreen shows “Windows protected your PC”. Choose **More info**, then
  **Run anyway**.

Updates through `anistream --update` are not downloaded by a browser and open without these
steps.
:::

mpv and ffmpeg are not bundled. anistream drives mpv for playback and shells out to ffmpeg when
muxing subtitles into a completed download. The `.deb` declares both as dependencies. On macOS and
Windows, install them yourself, as in Prerequisites below.

anistream's [player interface](/docs/guides/player/), with the skip button, Up Next, menus and
thumbnails, needs mpv 0.36 or newer. Older versions play with mpv's own controls; Ubuntu 24.04
ships 0.37 and Debian 12 ships 0.35. `anistream --doctor` says which version you have.

There is no Homebrew formula and no `cargo install` yet. To build from source instead, install the
prerequisites and then build.

## Updating

```sh
anistream --update
```

That downloads the latest release for your platform, verifies it against the published SHA-256,
and replaces the binary in place. Restart anistream to use it. The app also checks GitHub for a
new release once a day (one cached HTTPS request, nothing downloaded) and mentions it in a toast.
Turn the check off with:

```toml
[updates]
check = false
```

## Prerequisites

<Tabs syncKey="platform">
<TabItem label="macOS">

```sh
brew install mpv ffmpeg cmake
rustup toolchain install 1.97.1    # pinned by rust-toolchain.toml
```

</TabItem>
<TabItem label="Linux">

```sh
# Debian / Ubuntu
sudo apt install mpv ffmpeg cmake build-essential pkg-config

# Fedora
sudo dnf install mpv ffmpeg cmake gcc-c++

# Arch
sudo pacman -S mpv ffmpeg cmake base-devel
```

Install Rust from [rustup.rs](https://rustup.rs) if it is not already there. The toolchain version
comes from `rust-toolchain.toml`.

</TabItem>
<TabItem label="Windows">

```powershell
winget install --id Rustlang.Rustup
winget install --id Kitware.CMake
winget install --id NASM.NASM
winget install --id Gyan.FFmpeg
winget install --id shinchiro.mpv
winget install --id Microsoft.VisualStudio.2022.BuildTools
```

The Visual Studio installer needs the **Desktop development with C++** workload. The bare package
does not include the C compiler on its own. NASM is there because the torrent stack's crypto
assembles its own primitives on Windows.

Open a new terminal afterwards so the `PATH` changes apply, and check that `mpv` and `ffmpeg`
resolve. Some winget packages install the binary without adding it to `PATH`, and anistream looks
for both there.

</TabItem>
</Tabs>

## Build from source

```sh
git clone https://github.com/bitknox/anistream
cd anistream
cargo run --release
```

The first build is slow, since BoringSSL, librqbit and a WASM runtime are in the tree, and
incremental after that. The binary ends up at `target/release/anistream` if you want it on your
`PATH`.

Plugins always sit beside `config.toml`, whatever that path is. `anistream --plugins` prints the
directory in use. Logs roll daily, at `info` unless `ANISTREAM_LOG` says otherwise.

The player's controls, fonts and scripts and the upscaling shaders ship inside the binary, and
anistream writes them into the cache directory when it needs them. `anistream --doctor` prints
where the player files are. The tokens for joined plugin stores are kept wherever tracker tokens
are, which `trackers.token_storage` decides.

No config file is required. One is only written when you change something in the Settings screen,
and those writes are format-preserving, so comments you add by hand survive.

:::note[Running from cargo]
Running from `cargo` rather than an installed binary has one consequence for tracker and store
tokens: macOS keys keychain access on the binary, and every rebuild produces a new one. See
[token storage](/docs/guides/trackers-sync/#token-storage).
:::
